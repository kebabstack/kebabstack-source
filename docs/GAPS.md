# Current limits and adoption gates

Reviewed 2026-09-05 against the source. The former 2026-09-01 list was stale:
owner/admin/helpdesk roles, directory CSV import/export, Assets and Vault now exist.
Existence does not establish production readiness.

| Area | Current boundary | Before a production pilot |
|---|---|---|
| Release validation | Local compiler, frontend and PocketIC checks; no live-engine sign-off for this review | Deploy a clean candidate to a disposable engine; test installation, update, restart and restore |
| Recovery | Per-canister platform snapshots; no independent whole-suite backup/export | Define RPO/RTO, retain controller recovery, restore representative data, plan external exports |
| Identity lifecycle | The hub mints one stable id per person (0.17), moves every hub reference on a rename and seals a departed holder when an address is re-issued; apps still key their own data by e-mail until each is migrated to the id (SDK 0.3, roll-out in `docs/PERSON-IDS.md`) — an app on the old SDK sees a rename as one person leaving and another arriving | Update the hub before any app; migrate apps in the documented order; a person returning under a new IdP account is a new person until the planned `mergePersons` exists |
| Identity integrations | Incoming SSO accepts RS256, one audience, nonce and verified email; SCIM subset; OIDC provider alpha | Test actual Google/Okta tenant and each relying party; compare required SCIM filters/patch semantics |
| AI assistants | An assistant token (hub 0.19) is a new credential class: 30 days, one file on the person's computer, the whole person (no per-tool or per-app scoping), no refresh; writes rely on the chat client asking first, and app data reaching the model is untrusted text; the directory an assistant sees is the union of its owner's app pickers | Keep the lane off until people are briefed; treat a lost device like a lost password (disconnect in the menu or under Settings → AI); review the journal (kind `assistant`) with access reviews |
| Revocation | Bundled apps fail closed at 60 seconds; IdP sync latency and external OIDC sessions add their own delay | Measure upstream offboarding and downstream token/session expiry |
| External provisioning | No outbound SCIM; no SAML implementation | Keep the existing SaaS offboarding checklist |
| Trust | Device posture is self-reported by the osquery agent (a tampered device can lie); Windows installer is alpha; no access gating on posture; removal relies on the agent's hourly check; the osquery TLS lane has been exercised against real macOS agents only on one test engine | Pilot on a handful of managed devices per OS; keep MDM/EDR controls; treat the score as a signal, not an attestation |
| Public surfaces | Forms' fill pages and Trust's agent endpoints are reachable without sign-in by design; protection is rate limits, caps and unguessable slugs/secrets — no CAPTCHA, no per-source throttling | Keep public forms for low-stakes intake; review caps before a high-traffic form; rotate the enrolment secret if an installer leaks |
| Device sales | Invoices with a Swiss QR-bill from the register: numbers gapless per range, SCOR reference on a normal IBAN, VAT split half-up, the PDF archived as rendered — but rendered in the buyer's or admin's browser (pdf-lib), validated against SIX's published layout and a QR decoder, not yet against a bank's validation portal; no QR-IBAN/QRR, no payment reconciliation, no mail-out, two-decimal currencies only, the payment part in four languages | Validate the first PDFs with the bank's or SIX's QR-bill validation portal; confirm number range, VAT treatment and pricing rule with finance/HR; pilot with two or three sales before the offboarding flow depends on it |
| Large HTTP bodies (mo:json) | `mo:json` 1.4 parses in quadratic time: 81 KB ≈ 0.7 s, 161 KB ≈ 2.7 s, 323 KB ≈ 12.7 s of Wasm (≈ 30 B instructions → IC0522). Every outcall body must stay well under ~100 KB. Fixed in assets 0.8.2 (Apple 50/page + fieldset, Iru 100, Intune 100); **the hub's Okta pull still asks for 200 users per page** (`/api/v1/users?limit=200`, ~1.2 KB each) and would fail for orgs above ~150 users | Hub: page size 50 (next hub release); consider replacing the parser or streaming extraction for anything larger |
| Hub OIDC ES256 clients | The hub signs ES256 id_tokens in-canister with `mo:ecdsa`; the lane was never exercised live and its instruction cost is unmeasured (the assets IC0522 that looked like it turned out to be JSON parsing) | Measure `signJwt("ES256")` in PocketIC before offering ES256 clients; RS256 (1.9 B instructions, measured) stays the default |
| Silent lane refusals | An app that lacks a lane it uses (assets lacked *notify* until 0.8.4 because the manifest listed it as a want) fails silently: the hub answers ok=false, apps used to ignore it. assets now records and shows every refused notification; the other apps (desk, forms, trust, watch, bug, contracts) still `ignore` the answer | Audit every `hub_notify` call site for the same pattern; consider a hub-side "refused calls" counter per app on the Apps page so admins see it without opening the app |
| Apple Business Manager | Read-only sync of Apple's device register (devices + their device-management service); the browser signs the 180-day client assertion, the canister only stores it (in-canister ES256 with mo:ecdsa exceeded the 40 B instruction limit live — IC0522); gap list and adoption as *unknown*; verified live against one organisation (token, 200/page cursor paging, three services); renewal of the assertion is a manual step every ~6 months; no AppleCare coverage yet (one call per device); no release/assign actions by design | Add AppleCare coverage per device once the sync is trusted; consider a hub-wide reminder lane for expiring secrets (ABM assertion, MDM tokens) |
| Contracts | The AI reads what reaches one address; the check is structural (schema, allow-lists, quotes present in the text), not a judgement of truth — a vendor's mail can still say wrong things and a person must read the evidence. Text PDFs are read up to 40 pages; scans depend on the AI's vision input; minor units assume two decimals; the time zone is a fixed offset. The relay is a single Cloudflare worker with one key and no delivery guarantee beyond the sending server's retries and the optional fallback mailbox. No Gmail/Graph polling, no e-signature, no payments | Pilot with one team's contracts and the fallback mailbox set; review a month of proposals against the mails; decide whether a polling adapter or a second relay is needed before the company-wide address moves |
| Game data | Ship the Bug keeps published scores under the player's chosen name and an anonymous throw counter; publishing is opt-in per run and self-removal is one click, but there is no admin-side per-person export or erasure beyond the season reset | Treat boards as low-stakes social data; a leaver's scores stay until they remove them or an admin resets the season |
| Cost and scale | No validated operating-cost, capacity or availability benchmark | Measure a representative workload and staff time; agree a supported scale |
| Audit | Activity logs, bounded in-memory history; no independent immutable archive/retention policy | Establish export/retention requirements; do not claim audit certification |
| Delivery/retries | Push and third-party notifications can fail; no durable universal retry queue | Monitor sync ages and failures; specify the alert/retry path |
| Cryptography | Custom RSA signing/key generation remains security-sensitive; added verification tests are not a crypto audit | Independent specialist review before using Hub as a production identity provider |
| UX | Local smokes cover major role views; no representative-user study or accessibility conformance audit | Test keyboard, mobile, recovery and failure paths with actual operators/users |

These are tracked adoption limits, not features silently promised for the next
release. See OPERATIONS.md for current mitigations and POSITIONING.md for claims
that the code and evidence can support.
