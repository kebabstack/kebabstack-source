# Workspace entry, navigation and dialogs

Design 1.3.0, reviewed 18 November 2026. Source comparison starts at 6de57b4. These results use isolated browsers, synthetic users and the same routes on both sides of each comparison.

| Task | What changed | Acceptance evidence |
| --- | --- | --- |
| Find an app in Hub | The greeting and app search lead into a compact directory. The app name and description share a reading edge. | In Chrome at 1280 × 800 the first app moved from y=495 to y=358. At 640 × 320 it moved from y=466 to y=260. Search, Escape, favourites and the global launcher worked. |
| Reach account actions | The global account panel owns scrolling when content exceeds the viewport. Hub console overlays also bound their content height. | In 640 × 320 the account panel ended at y=406 before and y=307 after. Its Sign out button was reachable. The profile dialog went from y=−21…341 to y=16…304. The real browser kept keyboard focus inside the profile and its nested photo crop. Cancelling the crop returned to Change photo. Saving, removing the sample image and returning to the visible account button all worked. Hub navigation stayed at y=0 during actual scrolling at desktop, tablet, phone and landscape sizes. |
| Import or share a form | Native modal focus and one scrollable panel keep the title, fields and actions reachable. Editing an analyzed outline invalidates its preview. | Chrome and WebKit exercised import and share at 1280 × 800, 320 × 568 and 640 × 320 in light and dark themes. The populated import at 320 px previously extended from y=−177 to 745. It now fits from y=16 to 552 with scrollable content. At 320 × 568, collapsing the optional format guide increased the initially visible outline editor from 6 to 166 px. Escape restored keyboard focus. |
| Create a teamspace or paste a contract | Contracts uses the same dialog geometry. Directory suggestions are keyboard buttons and delayed results are checked against current input. | At 640 × 320 the teamspace dialog went from y=−48…368 to y=16…304. Both engines could reach the final action and dismiss the dialog. |
| Configure Crumbs on a phone | General settings fields shrink within their grid column. | A 320 px viewport previously yielded a 328 px document. The timezone search and fields now fit. |
| Sign in and switch tools | The Hub starts provider verification immediately. A current company session can go straight to identity validation and the authorized ticket. | Five alternating Chrome runs per case with synthetic response delays. Median callback to verified destination was 1,591 ms before and 1,002 ms after. Median signed-in switch was 755 ms before and 617 ms after. These measurements start at Hub navigation and end before the destination app loads. |

**Other signed-in surfaces.** The browser review covered 21 routes across Desk, Assets, Doku, Watch, Trust and Crumbs at three sizes. All 63 final observations fit horizontally. On the 59 scrollable views the global bar stayed at the top. Role-specific frontend smokes run separately. Kitchen bootstrap, the standalone games, public guest flows and assistive technology have different workflows and are outside this 63-view sample.

**Repeat the focused checks.** Run the module frontend smokes and the suite checks. For native dialog geometry use `npm run test:layout` with Chrome installed and a Playwright module available through `KEBAB_PLAYWRIGHT_MODULE`. The layout fixtures exercise the Hub profile and nested crop as well as Forms, Contracts and Crumbs against local synthetic responses. The German and English product website records its independent review in the website module’s VALIDATION.md.

**Release boundary.** Representative local checks cover access decisions, retries and focus restoration. The company IdP, end-user MFA, screen readers, full data-volume coverage for each module and every production role require separate verification. The release procedure checks exact packages and previous-release upgrades before production use.
