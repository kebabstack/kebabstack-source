# Data and privacy

Crumbs is designed to support a GDPR-compliant deployment. This is not a certification or a blanket consent exemption. Legal basis, ePrivacy/national terminal-access rules, notices, controller/processor arrangements, operator jurisdictions and actual site configuration still require assessment. The EDPB's [Guidelines 2/2023](https://www.edpb.europa.eu/our-work-tools/our-documents/guidelines/guidelines-22023-technical-scope-art-53-eprivacy-directive_en) explain why removing cookies alone does not settle the terminal-access question.

The tracking script reads the current URL, referrer, user agent through HTTP, page visibility and scroll. It writes no cookies, localStorage or sessionStorage. When configured for consent, it sends nothing until granted; withdrawal clears the browser queue. GPC and DNT disable collection. The authenticated employee dashboard separately uses the suite's browser session storage contract; do not equate dashboard login with public tracking.

Native mode receives the visitor IP from gateway metadata and the request URL/referrer and User-Agent through replicated canister ingress. It derives a site-specific daily pseudonym using a random daily HMAC secret, then persists only normalized analytics events and HMAC rate keys. Raw IP/UA are not stored in application event state, but the subnet processes the original ingress payload. Do not claim that raw addresses never reach the canister or that replicas erase ingress immediately. The current secret is stable state and survives same-day upgrades; daily replacement cannot erase historical snapshots.

The optional Node collector instead handles IP/UA at the trusted ingress, derives daily pseudonyms and queues normalized events on local disk. In this mode raw IP/UA and salts are not sent to the canister. These pseudonyms and event data may still be personal data; do not label hashing as guaranteed anonymization. Daily rotation intentionally prevents long-term returning-user cohorts and cross-day attribution.

Query strings and fragments are stripped from stored paths; only allowlisted campaign parameters contribute to dimensions. Email-like values, JWT-like strings, UUID path segments and long numeric path IDs are redacted. This is heuristic: names, short identifiers and other personal data can still be present in paths, campaign labels or properties. Configure excluded path prefixes and property allowlists, avoid sensitive event names and review a sample export. Imported historical dimensions retain their source values and need a separate privacy review before import.

Raw request bodies, visitor IPs and Authorization headers must not appear in proxy access/error logs, tracing or crash collection. Gateway/TLS configuration and infrastructure hardening are operator responsibilities. Native mode supplies no geography. Optional Node GeoIP uses a local database with separate licensing and update work.

Site retention is 1–1827 days. Expired native and historical data is excluded immediately from reads; the backend physically sweeps up to 1,000 events and 1,000 historical rows per 30-second timer tick, so a full sweep depends on retained volume and engine availability. Deleted sites are inaccessible immediately, their keys revoked, and IDs cannot be reused. There is no claim of instantaneous erasure from storage or snapshots.

In optional Node mode, delivery receipts/rejected rows expire after 24 hours; pending rows remain until delivered or explicitly handled by an operator, and the backend rejects events older than seven days. A capacity/auth outage retains pending data, so operators must resolve it and monitor oldest pending age. SQLite uses secure_delete and truncates its WAL when rotating salts, but storage snapshots, crash dumps and SSD behavior can retain previous bytes. Exclude salts and delivery queues from long-term backups; use encrypted, short-lived operational recovery copies and document deletion. Canister/Vault snapshots have their own retention policy. A snapshot restore may resurrect previously deleted events: apply retention and deletion instructions before reopening access.

Share links are separate bearer capabilities with explicit scope and expiry. Anyone with a valid link can view that site's reports. All report/share keys are tied to an issuer currently authorized to manage that website and fail closed after the 60-second Hub directory lease. Removing or demoting a website manager deletes their website credentials, including shared links. Both native collection and the optional signed collector remain independent of employee access so an identity outage does not discard telemetry. Controller and infrastructure-operator access is outside application role isolation.

Running on your own Cloud Engine does not automatically guarantee a country of processing or confidentiality against all node operators. Verify the chosen topology, ingress, gateways, controllers, backups and access arrangements before making data-residency claims.

## Additional reporting and optional integrations (0.6.0)

The tracker strips fragments, non-campaign query parameters and recognized email/UUID/numeric path identifiers before transport; the backend still normalizes all intake. Redaction is defense in depth, not a guarantee that arbitrary URLs or custom labels are anonymous. GPC, DNT, consent and browser blockers remain respected. `crumbs.status()` exposes only local delivery state, never a report key or visitor profile.

Search Console loads Google's sign-in SDK only after an explicit connection action. A read-only OAuth token is held in memory for that refresh and is never written to Crumbs state. The public client ID and exact property are saved for website managers. The latest aggregate report is shared with website readers. Search terms are off by default and recognizable identifiers are excluded; an operator must still evaluate free-text sensitivity. Disconnect removes the saved report; expiry follows website retention, with physical cleanup on the normal timer. Google account permissions and Google-held copies have their own lifecycle.

The Data Studio connector deliberately sends aggregate reports to Google. Every viewer supplies an expiring website Read key; keys reside in that viewer's Apps Script properties, not in tracker code or report parameters. The deployment fixes the collection origin and HTTP redirects are disabled, so editable report parameters cannot redirect a stored key to another host. Revoke expired/unneeded keys and manage Google sharing/retention separately.

Optional Node mode can use a licensed local GeoIP Anonymous IP/Plus database to exclude hosting-provider ranges (`CRUMBS_NETWORK_DB`). No IP lookup goes to a remote service; the classification is not stored in analytics events. This can also exclude humans using corporate proxies or hosting-based VPNs. Native mode has no datacenter-IP database. The built-in UA filter and small explicit referrer-spam list are heuristic and cannot certify that every counted visit is human.

No cookie is not equivalent to an automatic GDPR/ePrivacy exemption. The deployment's actual infrastructure, ingress logs, snapshots, recipients, legal basis and notices must be assessed. Crumbs does not claim universal GDPR certification, EU-only residency, or absence of personal-data processing.
